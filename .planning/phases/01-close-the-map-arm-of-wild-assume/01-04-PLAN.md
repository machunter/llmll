## The three sentences the release notes must carry

These are acceptance criteria, not suggestions. The entry must contain each of the following
verbatim, so that the evidence limit survives paraphrase:

1. `This closes a measured member of the SAFE-ARG class with no reaching-SAFE witness.`
2. `The phase closes a class member; it does not refute a demonstrated exploit.`
3. `The corpus run is recorded as a regression check, not as evidence the fix works.`

Both the return shape and the argument shape crash on a sort mismatch before a verdict, so the arm
is neither known exploitable nor known safe. That is the fact the three sentences protect.

## Prohibitions specific to this plan

1. Do not carry the v0.14.73 entry's framing across. That entry describes a defect that reported
   SAFE and wrote a sidecar for a program that reads past the end of a buffer, which is a claim
   this phase cannot make. The vocabulary to keep out of the new section is listed in the
   acceptance criteria as a region-scoped check.
2. Do not expand `LLMLL.md` beyond the version banner on lines 1 and 5. What the bare wildcard
   denotes in §3.4.6 is `REQ-wildcard-semantics-spec`, which sits in the deferred backlog
   (`.planning/REQUIREMENTS.md`, "Obligations and spec text"). Writing it here schedules a deferred
   requirement without a decision.
3. Do not touch `compiler/src/` or `compiler/test/` in this plan. The code is settled by plan 01-03.
