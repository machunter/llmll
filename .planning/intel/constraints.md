## The decidable boundary — `Sigma_auto`
- source: docs/design/data-scope-extension.md (Posts 1, 5, 7); docs/compiler-team-roadmap.md (Future, Data Scope Extension)
- type: nfr
- content: The verification boundary is **decidability**, the guarantee that "SAFE" is a decidable predicate on a fixed VC. `Sigma_auto` covers integers (QF-LIA), non-recursive tagged unions, closed length measures, bool, and since Lever A the theory of arrays: index-in-bounds on `bytes[n]` buffers and get-after-put / key-presence on maps with `{int,string}` keys and `{int,bool,string}` values. What is still outside: the *contents* or *structure* of a list (Lever B, unshipped) and any *recursive* data structure (Lever C, fenced). Lever C is undecidable in general and therefore **cannot live in `Sigma_auto`** without breaking the guarantee; it needs a new weaker tier or routing to the Lean tier.

## Lever comparison — decidability per extension lever
- source: docs/design/data-scope-extension.md (Post 7); docs/compiler-team-roadmap.md (Data Scope Extension table)
- type: nfr
- content: **Lever A** (theory of arrays for `bytes[n]` / `map[k,v]`): QF theory of arrays (`select`/`store` + extensionality), **decidable**, polite-combines with QF-LIA, **stays in `Sigma_auto`**; SHIPPED v0.14.33-51. **Lever B** (dependent lengths `list[t]{len=n}` + widened measure catalog): QF-LIA + EUF (+ arrays), **decidable**; proposed, depends on Lever A, overlaps R1. **Lever C** (inductive datatypes + induction, measure unfolding, PLE, refinement reflection): inductive datatype theory, **undecidable in general**, **leaves `Sigma_auto`**; research frontier, gated on LEAN-GA.

## SAFE-ARG defect class — a fact asserted from an unvalidated declaration
- source: docs/design/finding-arg-position-false-safe.md (Rev 2); docs/compiler-team-roadmap.md (SAFE-ARG row)
- type: nfr
- content: The first defect on the FQ-RESULT-SORT line that did **not** fail closed. `compatibleWith`'s bare-wildcard clause let a `bytes[32]` reach a `bytes[64]` parameter through one unannotated hop; `bytesLenReft` then asserted `bytesLen(b) = n` from the declared parameter type and index-in-bounds discharged against it, so the run reported `SAFE` and persisted a `verified` sidecar. Affected v0.14.34..v0.14.72. **The argument position is what makes it live**: at a return position the same laundering also injects a false fact, but the enclosing VC equates `result` with a call binder that `typeToSort` collapses to `FQInt`, so the constraint is ill-sorted and the solver refuses it; at an argument position the false fact lands on a parameter of a function verified independently, whose VC contains no call binder for it, so nothing crashes. **Precise consequence:** codegen's own dynamic bounds check traps at runtime, so the generated program does not read out of bounds; what is falsely certified is the obligation. The advisory must not say "certifies an out-of-bounds read". **The anti-laundering kernel cannot catch it**: `LLMLL.md:1060` scopes the invariant to field coherence, not antecedent truth, and here every field coheres.

## WILD-ASSUME — the fix seam and its discriminant
- source: docs/compiler-team-roadmap.md (SAFE-ARG row); docs/design/finding-arg-position-false-safe.md (Rev 2)
- type: api-contract
- content: A bare inference wildcard, and its `freshenFnType` instances `?$N` (which is why exact equality with `TVar "?"` left the first implementation completely dead), no longer satisfies a type that asserts a fact no obligation discharges. Two seams: `structuralUnify` for arguments (the live path) and `compatibleWith` for returns and `checkExpr`; **actual side only**. `.verified.json` gains `checker_soundness_version`, stamped unconditionally so absence is a sound stale signal, and sidecars in the affected range revalidate once. Measured **non-members** of the class: refinement aliases and nullary enums, whose type-level data is an obligation on the producer rather than an assumption.

## RET-RESOLVE — rule, side conditions, and prediction gate
- source: docs/design/ret-resolve-proposal.md (Rev 2)
- type: api-contract
- content: `tau_ret = lfp above tau^0 of F`, where `F(Delta)(f) = tau` if `Delta(f) = TVar "?"` and `Gamma_Delta |- body(f) => tau` with `tau` concrete, else `Delta(f)`. `F` is monotone on a product of flat lattices, so Kleene iteration converges (Cousot and Cousot, POPL 1977; Kildall, POPL 1973). This is **not a join**: "concrete wins over the re-synthesized value" is a `tau^0`-biased update, so it must be stated as Kleene iteration of a monotone update rather than with lattice-join notation. Bound: one pass per SCC in reverse topological order. Components are **intra-module by construction** (`buildCallGraph` runs over entry-module statements; the loader's post-order DFS with cycle detection forbids cross-module recursive groups), so SC3' does not generalize across imports. Corpus census over 151 `.llmll` files: 937 definition heads, 102 unannotated, 30 unannotated and contracted, 18 wildcard `tau_ret` (15 contracted), of which 10 resolve transitively to `int` (all contracted), 3 to a type the reader cannot name, 5 are hole bodies; **zero cycles**.

## The sort-precision conversion rule
- source: docs/design/ret-resolve-proposal.md (Background)
- type: nfr
- content: Each increment of sort precision on one side of the reflection equation converts a silently recovered constraint into a crash on the other, until both sides derive from one source. Witness: `E_str` returned a correct REFUTED at v0.14.71 and CRASHes at v0.14.72 because `tau_ret` makes the call binder `Str` while `result` stays `FQInt`. `R_result` is the next latent instance: making `calleeRetSort` alias-aware converts it to a crash exactly as stage (b) did for `E_str`. Shape-by-shape re-scoping schedules that conversion for later.

## R8 soundness premises — P1 contract preservation, P2 modular VCs
- source: docs/design/incremental-reverify-r8-proposal.md (Soundness argument)
- type: nfr
- content: **P1, contract preservation.** `patch` fills only body-position holes; contract-position and `?proof-required` holes are excluded from the checkout/patch dependency graph (`HoleAnalysis.hs:622,680`), so a patch **never changes any function's contract**. **P2, modular verification conditions.** Verification is assume-guarantee modular: a function `F`'s body-VC is emitted from `F`'s own precondition and its callees' **contracts**, never another function's **body** (`FixpointEmit.hs:32-34`); no cross-function body coupling exists in the emitted `.fq`. Conclusion: re-verifying exactly `{F}` discharges every obligation the whole-module re-verify would; the slice is sound, complete, and a singleton. A fill introducing a new call `F -> G` does not enlarge the slice, because `G`'s contract is an input, not an obligation to re-discharge.

## LEAN-GA is a three-layer rebuild, not a next-sprint integration
- source: docs/design/leanstral-integration-scope.md §1
- type: nfr
- content: The parking-lot framing "LEAN-GA is blocked only on `lean-lsp-mcp` availability" is wrong on three independent layers, only one of which the Leanstral 1.5 news touches. Layer 1: `LeanTranslate.hs` translates the *contract*, not the *obligation*, so the emitted theorem is misstated (structurally unfaithful; a rewrite). Layer 2: the obligations that most need Lean land at `erBodyFallback -> asserted` and are never marked `?proof-required`, so the pipeline never sees them (accurate, but never routed; rework). Layer 3: `lean-lsp-mcp` exposes Lean *language-server* primitives, **not** a `prove(theorem) -> proof_term` tool; the `MCPClient.hs` non-mock branch is a stub built on a wrong assumption. Value (discharging the roughly 20% non-QF-LIA tail plus the C-property) is real but gated behind all three.

## Model-untrusted, kernel-trusted — why T-B is the right shape
- source: docs/design/leanstral-integration-scope.md §4
- type: nfr
- content: T-B maps exactly onto the core thesis, an agent hallucinates a candidate and the compiler checks it, applied to proofs: Leanstral hallucinates a proof, the Lean kernel checks it. The model is untrusted proof *search*; the kernel is the trusted *gate*. Consequences: (1) model non-determinism is irrelevant, because the durable checkable artifact is the returned **proof term**, not the model call, which is precisely the PROOF-ARTIFACT C-property mechanism; (2) the C-property survives the whole stack **only if layers 1-2 are fixed first**, since a kernel-checkable certificate over a misstated theorem is worse than none.

## OBLIG-0 obligation report — top-level JSON schema
- source: docs/design/oblig-0-spec.md §2.1 (Rev 8, APPROVED)
- type: schema
- content: `{ "schema_version": "0.12.0", "source_file": …, "cross_module": "unsupported", "obligations": [ … ], "summary": { "total", "open", "discharged", "deferred", "asserted", "refuted" }, "refuted_fns": [ ], "effect_summary": [ { "function": …, "effects": … } ] }`. `effect_summary` (Bundle B0) is one name-sorted entry per function whose `effects` is either a sorted array of coarse capability labels (`stdout`, `fs.read`, `fs.write`, `net.http`, `random`, `crypto`) or the string `"unbounded"` (top: may exercise any capability, including outside the catalog). It is a sound **may-over-approximation** over the call graph; top is reached at opaque boundaries (`?delegate` / `?delegate-async` / `?delegate-pending` / `?scaffold` holes, `haskell.*` / `c.*` FFI, unrecognized `wasi.*`). It is **informational** and never affects a function's trust tier, `EvidenceRecord`, or `--strict-verified-core` admissibility (authority is orthogonal to trust).

## OBLIG-0 obligation object — three-channel shape
- source: docs/design/oblig-0-spec.md §2.2 (Rev 8)
- type: schema
- content: A single obligation object carries `id`, `origin` (an RFC-6901-style pointer), `kind`, `backing`, `status`, `function`, plus three channels. `type_channel`: `expected_type`, `polymorphic`, `in_scope` (name / type / source). `contract_channel`: `preconditions`, `postcondition_goal`, `path_condition` (guard + kind), `path_truncated`, `contract_fragment`, `body_fragment`, `body_faithful_possible`. Plus a trust channel. Design principle: v0.10 **primarily re-exports** existing analysis; the one net-new component is the candidate-expression search (§7), scoped to `ObligationMining.hs` with bounded search and explicit "unverified" labeling. **It does not expand the TCB.**

## The `?` wildcard is not "any type"
- source: docs/design/ret-branch-pref-proposal.md (What `?` denotes); docs/design/ret-resolve-proposal-review.md (Round 1 finding 4, Round 4)
- type: nfr
- content: `TVar "?"` denotes *inference produced no usable type at this position*, not *any type*. `compatibleWith (TVar _) _ = True` is the Siek-Taha consistency relation, reflexive, symmetric, **not transitive**, so LLMLL implemented half of a gradual type system without naming it. In gradual typing `? meet tau = tau` is safe because every consistent-but-unequal use is guarded by a cast; `LLMLL.md §3.4.5` forecloses casts ("there is no dynamic safety net"), so there is no blame point and no gradual guarantee. That compatibility is therefore an **unchecked admission**, not a deferred check: a program admitted through `?` carries no runtime guard and no verification obligation recording the gap. Consumers must treat a result derived through `?` as unproven rather than trusted.

## Class-indexed conservativity — why the wildcard is refused at data-carrying positions
- source: docs/design/ret-resolve-proposal-review.md (Round 4, literature answers)
- type: nfr
- content: At **scalar** types a laundered wildcard yields a sort disagreement that **fails closed**; at **data-carrying** types it yields sort agreement with a false fact that **fails open**. Every system that admits the dynamic type at a type index pays with a runtime check or new normalization machinery (Lehmann and Tanter POPL 2017; Eremondi, Tanter and Garcia ICFP 2019; Ou et al. IFIP TCS 2004; Tanter and Tabareau DLS 2015). Since casts are foreclosed, **refusing the dynamic type at those positions is the only remaining sound option**. Design-reference alternatives: F*'s length-indexed buffers discharge the length equality at the call site; Dafny keeps length at the term level (`a.Length`) so no type-level lie is expressible.

## RFC-SWARM acceptance criterion — the completeness bar
- source: docs/design/rfc-swarm-roadmap-proposal.md §1
- type: nfr
- content: "A swarm implements a full RFC, verified" decomposes into four claims. **Completeness** = a disposition ledger over the whole normative surface plus a verified characteristic core, with the characteristic-core clause set **named and pre-registered before dispositions exist**. **The swarm** = concurrent, role-separated, brief-only agents. **Verified** = tier assignment per clause class, with the strict bar on the core. **Demonstrated** = mutation adequacy plus process integrity, **not** agent failure; the minimal-agent benchmark is saturated (0 grade-A across 69 attempts), so the verifier's error-catching value is established by construction via hand-written wrong fills, not by observed agent error. Standing rule from §5: do not widen `Sigma_auto` to rescue a target.

## RFC-SWARM STOP conditions, per phase
- source: docs/design/rfc-swarm-roadmap-proposal.md §4
- type: protocol
- content: **Phase 0**: halt and re-target if > ~30% of rubric-normative rows disposition out, **or any characteristic-core clause dispositions out**, or a core clause turns out inexpressible without Lever B. **Phase 1**: the blind-agent extraction arm failing does not block; it downgrades the extraction-role claim. **Phase 2**: if the pre-registered numeric trigger fires (wall clock >= sequential baseline, or conflict-retry fraction above the Phase 0 bound), ship as parallel-per-module cascades and sacrifice only the intra-tree half of the claim. **Phase 3**: a hole that exhausts retries is a *finding*, never a hint occasion; if >= 3 holes exhaust, pause and adjudicate; do not lower the bar mid-wave. **Phase 4**: a clause with no constructible refuting mutant is re-audited, either the contract is weak (fix, re-verify, record as a co-evolution exhibit) or the clause is re-dispositioned; neither silently ships.

## The RFC-SWARM claim, stated before starting
- source: docs/design/rfc-swarm-playbook.md §0
- type: nfr
- content: The claim the whole procedure supports, worded before any stage runs because the wording constrains every later step: "Given an RFC, an orchestrating agent builds a formal specification traceable clause by clause to the source text, and a swarm of blind agents produces an implementation that the compiler proves satisfies it. Every normative clause of the source is dispositioned: verified, modeled, tested, or excluded with a cited reason. The protocol core is verified body-faithfully." What it does **not** claim: that the RFC as a whole is "verified"; that agents would have failed without verification (the benchmark is saturated, so that is unfalsifiable); that `:source` provenance proves fidelity to the RFC; that trace-level or timing properties hold.

## RFC-SWARM roles and the firewall between them
- source: docs/design/rfc-swarm-playbook.md §1
- type: protocol
- content: Six roles with fixed visibility. **Orchestrator**, one long-lived agent, runs the playbook and spawns the others, may see everything. **Extractor**, 2+ agents blind to each other, produces the clause census from verbatim RFC text, may see RFC bytes + rubric only. **Disposition**, 1 agent, assigns class and disposition per row, may see the inventory + fragment capability. **Contract author**, agent(s), writes root contracts one clause per Encoded row with `:source`, may see the inventory + RFC. **Fill**, N >= 4 concurrent blind agents, writes function bodies and sub-decomposes via `refine`, may see **the checkout brief and nothing else**. **Auditor**, human, the named checkpoints and nothing else, may see everything. Standing anti-pattern: never let one agent both produce and audit the inventory, because self-audit cannot answer the completeness question.

## Stage-by-stage procedure and its per-stage failure modes (A through O)
- source: docs/design/rfc-swarm-playbook.md §2
- type: protocol
- content: **A intake**: fetch the RFC as verbatim text and record a SHA-256 of the exact bytes; every later stage reads those bytes, not a paraphrase; failure mode is extracting from memory, which cannot survive the clause-to-predicate audit. **B scope decision, before extraction**: fix the wire-format boundary (byte-level parsing of variable-length or NUL-terminated fields is string structure, outside the fragment; the core operates on decoded packet ADTs) and the ordering boundary (do not import an order the RFC does not define; reason by equality and disequality only, and record any needed order as a modeling decision). **C rubric before extraction**: pre-RFC-2119 documents have no MUST/SHOULD/MAY discipline, so write the normativity rubric first and apply it uniformly, with tie-breaks including one obligation per row and "when in doubt, mark normative". **D dual blind extraction** on identical bytes under the identical rubric; each row carries source, line span, verbatim quote, rule applied, strength word, one-sentence obligation; extraction assigns **no disposition**. **E reconciliation by line-span overlap, not prose similarity**, reporting three distinct things: line-coverage agreement (Jaccard), granularity difference separated from coverage disagreement, and rule agreement on one-to-one matched rows (where Cohen's kappa applies); then adjudicate every genuine disagreement by hand with the reason recorded per row. **F name the characteristic core before dispositions exist**, so the set cannot be drawn around whatever happens to succeed. **G disposition pass**: exactly one disposition (Encoded / Deployment-modeled / Vectored / Dispositioned out) and one class (C1 state transition, C2 arithmetic invariant, C3 length or format, C4 opaque primitive, C5 test vector, C6 timing-liveness-transport-trace) per row. **H feasibility probes before authoring**: verify the core shapes, then mutate and confirm the mutant refutes, in both directions for at least the main transition function and any joint or product invariant. **K root contract authoring**, one clause per Encoded row. **L coverage lint then freeze**. **M spawn the swarm**. **N refute layer and kill matrix**. **O writeup discipline**. TFTP figures: 119 and 125 extracted rows; Jaccard 0.866, kappa 0.938, 64 granularity differences, 11 genuine disagreements, 6 adopted and 5 rejected, canonical inventory 124 rows; core 15 rows; 46 Encoded, 20 Deployment-modeled, 5 Vectored, 53 excluded.

## Stage G2 — audit the artifact against the pinned bytes, on tokens not substrings
- source: docs/design/rfc-swarm-playbook.md stage G2
- type: protocol
- content: Run the citation audit **before** the feasibility probes and before the gate, because a citation that resolves to nothing should not cost forty-five minutes of probes, and gate J rules on exactly the rows this audit reads. Three checks are mechanical and **STOP**: the cited document is one that was pinned, the span lies inside it, and the quoted words come from that span. Match on **tokens, not on a substring**: a census legitimately abbreviates a long clause with an ellipsis and legitimately flattens a multi-line packet diagram onto one line, and the substring test calls both a broken citation, firing on 22 of 113 correct TFTP rows. Two further checks are mechanical and **reported, never thresholded**, because both fire on correct input: a span one line short of its own sentence (6 real TFTP rows) and a declared strength absent from the quote (3 real TFTP rows, all citing RFC 1123's requirements-summary table where strength is a column position rather than a word). The last check is a **reading and cannot be mechanised**: does the stated reason describe the clause it cites? Delegate it over the rows the gate reads (core rows and every excluded row) and require the verdict to quote the words it rests on from **both** sides, so the driver can check they occur; a flag it cannot locate in the artifacts is an assertion. A misread reason on a **characteristic-core** row is a STOP. Failure mode to avoid: auditing whether each disposition is *right*, which is a different and much larger claim; this stage asks only whether each stated reason matches the clause it cites.

## Stage H — do not commit probe bodies
- source: docs/design/rfc-swarm-playbook.md stage H
- type: protocol
- content: Probe bodies are working implementations of functions the swarm is meant to invent; committing them plants a reference solution in the tree. Carry forward the contracts and the verdicts only. Standing criterion: a contract that cannot refute its own historically-attested bug is decorative.

## Stage M — per-hole lock, per-FILE compare-and-swap
- source: docs/design/rfc-swarm-playbook.md stage M
- type: api-contract
- content: Checkout tokens are keyed by JSON pointer, so N agents genuinely hold N different holes at once, but `patch` validates against a **whole-source hash** and rejects anything older than the current file (`PatchAuthError: obligation context is stale`). **The first patch to land invalidates every other outstanding brief**, however unrelated the holes. This was already written down (`site/blog/post-4-who-writes-the-decomposition.md`: "a module carries a whole-file compare-and-swap … application to one module is serialized") and the first wave re-derived it the expensive way by wedging fourteen holes. Independently confirmed: two holes checked out concurrently, first patch `PatchSuccess`, second `PatchAuthError`. Retries carry compiler error text only, capped, with protocol-level conflict retries budgeted separately so concurrency cannot consume an agent's error budget. Per-fill bar, read per function: verify SAFE, the filled function in the body-faithful set, not flagged `termination_unverified`; the whole-tree `--strict-verified-core` check belongs at the end. Each agent gets a **pristine** scratch copy of the module, every hole still a hole; handing over the live tree would destroy the blindness the wave exists to demonstrate. A hole that exhausts its retries is a **finding**, routed to the compiler team or back to the inventory as a scoping error, never an occasion for a hint.

## Stage N and O — kill matrix with survivors, and writeup discipline
- source: docs/design/rfc-swarm-playbook.md stages N, O
- type: protocol
- content: Execute the pre-registered mutant taxonomy and report the **full kill matrix including survivors**: a mutant that verifies SAFE means the contract is weak or the row is mis-dispositioned, and it is resolved rather than dropped. Retain **good twins** (correct variants expected to stay SAFE) as the guard against over-strong contracts. Extend the refute requirement to Deployment-modeled rows so a modeled clause cannot ship with zero evidence its model constrains anything. Freeze the verdicts into the CI gate. Writeup: lead with the class-stratified coverage figure and the core count, not the raw ledger ratio; disclose every trusted step, including any closure from per-step invariant preservation to all-traces properties, which is a trace induction outside the decidable fragment; never frame the result as verification catching agent error.

## Pre-registration discipline
- source: docs/design/rfc-swarm-playbook.md stage I, §3 anti-pattern 5, anti-pattern 6
- type: protocol
- content: Fix in writing, before any wave agent runs: acceptance criteria; the measurement set; process budgets (semantic retries per hole, protocol retries counted separately, human interventions after freeze); the numeric concurrency trigger; and the **mutant-class taxonomy** per clause class, with historically attested bugs as mandatory members. Pre-registration only means something if it is honored when it goes against you: record outcomes in an **appendix** and never edit the pre-registered text; append an amendment with its reason instead. Never silently reinterpret a fired STOP; if the instrument turns out to be defective, say so in writing, show the argument, and let a human adjudicate the amendment.

## Chasing a coverage number is an anti-pattern
- source: docs/design/rfc-swarm-playbook.md §3 anti-pattern 1
- type: nfr
- content: Recovering excluded rows by modeling more state is legitimate only when the added state buys assurance. The test is "does this rule defend against something an attacker can do", not "is this rule expressible". Expressibility alone lets the ledger absorb transport mechanics that improve a percentage and prove nothing. Route any proposed coverage improvement through adversarial review before adopting it.

## The pipeline driver — what it automates, what it delegates, and what it pins
- source: docs/design/rfc-swarm-playbook.md §4
- type: api-contract
- content: `scripts/rfc_to_implementation.py` runs stages A-O from an RFC URL, is agent-agnostic (`--agent-cmd` is any shell command, the same abstraction `experiments/minimal-agent/scripts/run_agent.py` uses), is resumable (every stage writes its artifact and hashes it into `MANIFEST.json`; completed stages are skipped), and **enforces the STOPs rather than reporting them**. Three properties bound reliance on it. (1) It separates what it automates from what it delegates: stages are `mechanical` (A, E, J, L, and the scoring half of N: deterministic, no model), `agent` (B, C, D, F, G, H, I, K, M, O: a judgment a model makes under a written contract, schema-checked on return), or `gate` (G2, J, L, and the per-fill bar in M); the script makes no judgment it labels mechanical, and G2 is both kinds at once. (2) Blindness is **structural, not requested**: stage D's two extractors run in directories holding the pinned bytes, the rubric, and nothing else, and `--audit-blindness` re-checks after the fact and fails on any unaccounted-for file. (3) `--self-test` pins the mechanical spine to the first real run, replaying committed TFTP Phase 0 data and asserting the exact published figures (Jaccard 0.8655 / 0.725, kappa 0.9378, 124 rows, 46 Encoded, 15/15 core, 62/65 carried, RFC-COV-1 green). Stated coverage gaps: gate J's third condition is not evaluable on that artifact (the closed barrier list postdates the run), and stage G2 is pinned only in the half needing no source bytes, because the pinned RFCs are deliberately outside this repository. The self-test asserts the zero and prints the gap, on the ground that a condition skipped in silence is a gate kept green by its own blind spot. ## Spec-from-RFC pipeline stages S0 through S5
- source: docs/design/spec-from-rfc-pipeline.md §1
- type: protocol
- content: **S0 fragment scoping** (RFC + `Sigma_auto` boundary -> scope matrix, human with agent draft; pattern: `VERIFICATION_SCOPE.md`). **S1 clause extraction** (RFC **source text**, verbatim access not paraphrase -> clause inventory; agent, human-reviewed; template `examples/rfc1982_serial/VERIFICATION_SCOPE.md`). **S2 clause classification** (inventory -> per-clause translation class; agent, human-reviewed). **S3 contract authoring + `:source` binding** (classified clauses -> `pre`/`post`/`weakness-ok`/`check` with provenance; agent; shipped surface `LLMLL.md §4.6, §4.5, §5.1`). **S4 adequacy checking** (contracted module -> coverage + vacuity + mutant evidence; compiler + human; `--spec-coverage`, `--weakness-check`/`--cdp`, authored mutants). **S5 verification + freeze** (filled module -> verdicts + frozen CI gate; `verify --strict-verified-core`, `EXPECTED_RESULTS.json`). S0 runs **before extraction, not after failure**: the named failure mode is scoping optimism, promising `verified` for a clause that later classifies nonlinear, and the scope matrix is the headline rather than a post-hoc disclaimer. The inventory matters because `--spec-coverage` measures "functions with contracts" while no tool measures "RFC clauses with contracts"; the inventory is the denominator that makes the second ratio auditable.

## Clause translation taxonomy C1 through C6
- source: docs/design/spec-from-rfc-pipeline.md §S2
- type: schema
- content: **C1 state transition / table** ("in state S on event E, do X") -> totality `post` over enum + outcome sum; QF-LIA + acyclic datatype theory, **auto-discharged**. **C2 arithmetic invariant / range** (formulas, bounds, floor division) -> refinement `pre`/`post`; QF-LIA, **auto-discharged**, with nonlinear subterms needing restriction or landing `asserted`. **C3 length / format rule** -> length-measure `post` (`(= (len result) d)`); closed measure set, **auto-discharged**. **C4 opaque primitive** -> typed builtin + `weakness-ok` with a provenance-bearing reason; outside `Sigma_auto`, **trust channel**, `asserted`/suppressed. **C5 test vector** -> `check` block; dynamic channel, **executed, not proved**; **width-parametric**, since an RFC may state its examples at a different parameter width than the instance (RFC 1982 §5 uses SERIAL_BITS = 2/8), so vectors must be adapted to the instance width and **the adaptation recorded in the clause inventory**. **C6 untranslatable** (SHOULD-prose, liveness, timing, concurrency, security arguments) -> recorded exclusion in the scope matrix; spec is intentionally silent. A clause that classifies C2-nonlinear or quantified has two dispositions in preference order: restrict the surface form to stay QF-LIA, or mark it `?proof-required` so it promotes to the trust channel as `asserted`. **Weakening the predicate to silence the verifier is the named anti-pattern.**

## What `:source` claims — the provenance model
- source: docs/design/spec-from-rfc-pipeline.md §2
- type: nfr
- content: `:source` is a **traceability pointer, not a fidelity proof**. It claims that this clause was authored against that RFC location, and the claim survives into `--trust-report` output and `.verified.json` sidecars so an auditor can enumerate every contract-to-standard edge mechanically. It does **not** claim the predicate is a correct formalization of the cited text; nothing checks the string against anything. Audit procedure, human, per clause: read the cited RFC text and the predicate side by side; confirm direction (the RFC's MUST maps to the contract's obligation, not its assumption); confirm totality clauses are present when the RFC's table is exhaustive (the `step-weak` failure mode); confirm units and encodings (seconds vs steps in RFC 6238 §4.2 is exactly where a silent transposition would live). The S1 clause inventory is the audit's checklist.

## `:source` binding conventions
- source: docs/design/spec-from-rfc-pipeline.md §S3
- type: api-contract
- content: One `:source` string per `pre`/`post` clause, formatted `"RFC NNN §X.Y — eight-to-fifteen-word paraphrase"` (grammar `LLMLL.md:1979-1980`; semantics §4.6, pure metadata threaded to `--trust-report` and `.verified.json`). Provenance granularity is **CLOSED** at v0.14.65 (SRC-CONJ-1): formerly `and`-combining multiple `pre` clauses dropped `:source` as ambiguous, so a precondition drawing on two distinct RFC clauses could not carry both provenances; each authored clause now keeps its own `:source` (per-conjunct `contractPreClauses`/`contractPostClauses`; JSON-AST 0.9.0 `pre_clauses`/`post_clauses`; trust-report `pre_sources`/`post_sources` in author order). C4 convention: `weakness-ok` functions have no `pre`/`post` to suffix, so RFC provenance lives in the reason string; this is a convention, not a checked channel. The playbook adds the executed citation convention: every `:source` begins with a bracketed inventory tag, `"[T045] RFC 1350 p.4 - ..."`, because exact tags are what make coverage mechanically checkable and a completeness claim cannot rest on fuzzy matching.

## S4 adequacy — four checks, and the mechanized floor is shape-dependent
- source: docs/design/spec-from-rfc-pipeline.md §S4
- type: nfr
- content: Three mechanized checks plus one human loop, in order of what they actually catch. (1) **Coverage**, `--spec-coverage`: every function contracted or `⊘`-suppressed with a reason. (2) **Vacuity**, `--weakness-check` (trivial-body pass) and `--cdp` (counted discriminative power): catches a translated clause so weak that identity/constant bodies satisfy it. (3) **Refutation witness**: an authored mutant per core invariant; a clause translation without a refuting mutant has no evidence it constrains anything. (4) **The human co-evolution loop**, the check that does not mechanize: an under-specified post lets a wrong body verify SAFE (`step-weak`). **The mechanized floor is shape-dependent** (n=2 across two RFCs, F-1982-4): no flag fires on the totality-omission shape, but `--weakness-check` *does* fire on an implication-only bool post (`serial-lt-weak`), so the floor is higher than "nothing fires" for one shape class and the human-loop conclusion stands for the rest. CDP measures vacuity against a closed candidate catalog, not fidelity against the RFC; `adv-spec-weaken-0` finding F-002 settled that the self-attestation channel has no per-instance oracle (`LLMLL.md §4.4.6`). The pipeline makes weakness **visible and enumerable**; it does not auto-detect it.

## Pipeline generalization limits and the four degenerate inputs
- source: docs/design/spec-from-rfc-pipeline.md §3
- type: nfr
- content: **Translates today, with evidence:** state machines over finite enums with payload-bearing outcome sums (C1, reaches `verified`); linear arithmetic invariants, ranges, floor/mod arithmetic within QF-LIA (C2); fixed-length/format rules within the closed measure set (C3); appendix test vectors (C5). **Does not translate:** cryptographic function correctness (C4, governed suppression, `asserted` at best); liveness, retransmission, timing and concurrency text (C6, and `Sigma_auto` has no temporal fragment); unbounded-data invariants over lists/arrays/maps (blocked on the data-scope track, Lever A first); SHOULD-level prose (policy, not predicate). **Four degenerate inputs the pipeline must classify rather than mishandle:** (1) a clause spanning two RFC sources, one clause whose `:source` cites the operative section with the delegation chain recorded in the inventory row, mechanized by SRC-CONJ-1; (2) a constructor-valued test vector, where the `check` block parses but the property evaluator skips constructor-valued vectors, so the content is carried by the C1 post instead; (3) an RFC clause quantified over unbounded time, which is C6 or C2 restricted to the per-call obligation, with the temporal claim recorded out of scope; (4) a `weakness-ok`'d function later given a contract, where W602 fires, the contract wins, and `weakness-ok` is reported redundant.

## RFC target admissibility criterion — six clauses over the characteristic core
- source: docs/design/rfc-swarm-target-selection.md §2
- type: nfr
- content: Every core row must sit inside the shipped fragment. Across three runs, everything that put a row out was `B5` (string structure) or `B4` (opaque transform), so the criterion is stated as the absence of those **in the core**, not in the document. A candidate is admissible when all six hold of the clauses that make the protocol *that protocol*: (1) the core is state transitions and fixed-width field values, not byte-stream layout; (2) no core obligation requires locating a field whose offset depends on another field's value (ARP's `8 + 2*ar$hln + ar$pln` accounts for 22 of its 34 excluded C1-C3 rows); (3) no core obligation concerns position within, or insertion into, an output sequence (this is what halted RFC 4648: an encoder must not *add* line feeds, adding is a stream operation, and no per-quantum model carries insertion between quanta); (4) no core obligation rests on an opaque transform; (5) timing and liveness clauses may exist but must not be characteristic; (6) roughly 20 to 25 roots, with undershooting the failure mode, since a five-clause core cannot exercise a wave.

## Three strictly nested fragments bound the agreement instrument
- source: docs/design/spec-agreement-proposal.md Rev 1 §1, §6.2; docs/design/spec-agreement-review.md F-1, F-5
- type: nfr
- content: `Sigma_auto` (verification) = QF-LIA, acyclic datatypes, enums, closed measures, bool, plus Lever A arrays and maps (`LLMLL.md §5.3.3`). `Sigma_subsume` (`RefineReuse.hs:281-299`) = QF-LIA **scalars only**; any constructor, measure, pair, `Result` term or array op abstains, because the bare two-constraint `.fq` declares no UF constants. `Sigma_witness` (`Feasibility.hs:187-191`) = **Int and Bool base sorts only**, for parameters and the declared return type; `baseSortText` returns `Nothing` (abstain) for every other type after alias and refinement resolution, and `witnessOf`/`minimizeWitness` (`:256-284`) range only over `qInputs`. The review estimated the comparable set at "roughly a fifth to a quarter" of `Encoded`; the measurement puts it at **10.6%** (§0). Consequence of the third fragment, new in Rev 1: widening comparison to constructor terms unlocks the C1 transition rows whose distinguishing input **is** a constructor value, and that value cannot be rendered, so those rows return a bare "these differ" bit with no exhibit. The eliminative claim survives (the solver's `sat` verdict establishes that a distinguishing input exists, falsifying "both readings are faithful", without depending on rendering the model); what is lost is the adjudication affordance, not the soundness of the defeat.

## SPEC-AGREE-1 — which layers are worth agreeing on
- source: docs/design/spec-agreement-proposal.md Rev 1 §2
- type: nfr
- content: **Clause census**: yes, already adopted (the failure mode, overlooking a clause, is roughly independent across agents; TFTP Jaccard 0.866, Cohen's kappa 0.938, read as a reliability statistic only). **Disposition**: no, it follows from the fragment's documented limits, which every agent reads from the same source. **Architecture and signatures**: not mechanically, since structural comparison of module decompositions has no decidable equivalence check. **Contracts given fixed signatures**: yes, **within `Sigma_subsume`**, a solver query on 10.6% of rows today and on more after the constructor backend. **Bodies given a contract**: already covered by R5 `checkout --multi` + `diverge-report`. The R5 duality is sharper than "two halves of the same question": `diverge-report` classifies observational divergence among verifying fills, an extensional relation on behaviors; subsumption is an intensional relation on predicates whose refinement-calculus meaning is inclusion of implementation model classes.

## SPEC-AGREE-1 — what agreement can and cannot claim, and four threats
- source: docs/design/spec-agreement-proposal.md Rev 1 §4
- type: nfr
- content: **Claims:** that N independent formalizations of a clause were produced blind and their logical relationship was decided mechanically **on the comparable fragment**; that every non-equivalence was adjudicated against the verbatim source with a recorded witness **where one could be rendered**. **Does not claim:** that an agreed contract is correct. Agreement is evidence about fidelity only in the eliminative direction, as a defeater generator. The defensible wording is about the clause, not the contract: *N formalizations produced under framing F were pairwise equivalent, so no ambiguity in this clause was detectable at framing F*. Four threats bound it. **T1 correlated error** (Knight and Leveson, IEEE TSE SE-12(1), 1986; limiting, not fatal, and Eckhardt and Lee and Littlewood and Miller give the difficulty-function model under which forced methodological diversity can drive covariance negative). **T2 agreement on a vacuous contract**: weak contracts are the agreement attractor, so vacuity is a **confound of the statistic itself**, not merely a downstream filter, handled by stratification rather than by `--cdp` alone. **T3 framing by the frozen signatures**: the rate is conditional on an architecture that itself encodes interpretive decisions, and for C1 rows the frozen outcome sum may already contain the answer; **measured, not only disclosed**, by re-running one arm against the same signature with constructor and field names mechanically replaced by opaque `A0..An`, sorts preserved. **T4 the obligation-gloss priming channel** (new in Rev 1): the inventory row's one-sentence obligation authored at stage D is a prior formalization of the same clause in prose fed identically to all N arms, sitting at the same layer as the artifact being produced, and is **a larger leak than T3**.

## Agreement is evidence only in the eliminative direction
- source: docs/design/spec-agreement-review.md F-8; docs/design/spec-agreement-proposal.md Rev 1 §3 (Reporting rule)
- type: nfr
- content: Separate three propositions: (P1) predicate phi is a faithful formalization of clause c; (P2) the implementation satisfies phi; (P3) the implementation does what c requires. LLMLL mechanizes P2. P1 is not a formal proposition because c is a natural-language artifact, so it is the validation question rather than the verification question, and **no mechanical procedure can be positive evidence for it the way a proof is evidence for P2**. What a mechanical procedure can do is produce *defeaters*: a witness showing two candidate readings differ observably falsifies the conjunction "both are faithful". Agreement yields no corresponding entailment. Built as a defeater generator the claim is defensible; built as a confidence meter it is not. **The rate is confounded**: weak contracts are the agreement attractor, so agreement rate is positively correlated with contract weakness by construction, and the unstratified rate is uninterpretable in principle. Rev 1 adopts this without qualification and makes detection yield the headline.

## The ledger records what the verifier carries
- source: docs/design/spec-agreement-review.md F-10; docs/design/spec-agreement-proposal.md Rev 1 §1, §5 EC3
- type: protocol
- content: Subsumption abstention is a limitation of the bare-`.fq` driver, not a statement about the verifier. Acting on the inverse inference would re-disposition correct C1 and C3 rows out of `Encoded` to preserve a tool's applicability claim, **corrupting the ledger to protect the instrument**. `Not-comparable` must be a first-class per-row outcome inside the **full** `Encoded` denominator, reported alongside equivalent, ordered and incomparable, never dropped and never routed back to the inventory. Rev 1 promotes this from an edge case to **the scoping rule**: the ledger records what the verifier carries, and the instrument reports its own reach rather than trimming the ledger to match it. Positive witness for the modal outcome, taken from the committed corpus rather than constructed: in `examples/tftp_rfc1350/wave/tftp-filled.ast.json`, def `opcode-of`, the post clause `{"kind":"op","op":"=","args":[{"kind":"var","name":"k"},{"kind":"var","name":"KRRQ"}]}` makes `ufBearing` return `True` at the `var` node named `KRRQ` (uppercase head, nullary constructor term); verdict `not-comparable`, the row stays in the denominator, no witness, no route back. This shape fires 13 of 18 times in the abstention histogram.

## SPEC-AGREE-1 edge cases the design must handle
- source: docs/design/spec-agreement-proposal.md Rev 1 §5
- type: protocol
- content: (1) **An agent omits a row entirely**: a coverage gap, not a disagreement; RFC-COV-1 (`scripts/rfc_coverage.py`) catches an `Encoded` row cited by no clause. (2) **Both agents produce a vacuous contract**: equivalent and worthless, so the agreement record carries the CDP verdict beside it. (3) **Subsumption abstains**: a first-class per-row outcome inside the full denominator. (4) **A row whose citing clauses straddle a comparable and a non-comparable contract** (new in Rev 1): `:source` citations are per clause and one row can be cited from more than one `def`, so the conservative rule is that a row is comparable only when **every** clause citing it lives in a comparable contract; without this stated, two implementations publish different denominators from identical data. (5) **An agent writes a `pre` and declines the `post`**: `toFQ = maybe (Just FQTrue) exprToPred` (`RefineReuse.hs:188`) reads the absent post as `True`, so the arm registers as *strictly weaker*, a lattice position rather than a coverage gap; route absent clauses to EC1 before comparison. (6) **A parameter named `result`** (new in Rev 1): `alphaRenameMap` (`RefineReuse.hs:106-112`) gives the parameter mapping priority, leaving the postcondition result binder unnormalized, which the QF-LIA gate does not reject; under frozen signatures it is preventable, so **"no parameter may be named `result`" joins the stage-K freeze rules**. (7) **N agents produce N distinct readings**: pairwise non-equivalence is not transitively closed, so this is two outcomes; a chain `A ⊏ B ⊏ C` has a canonical disposition (take the weakest reading that still kills the pre-registered mutants, then apply the three discriminators), and only a three-way antichain escalates as ambiguity.

## Process attestations stay out of the trust-tier vocabulary
- source: docs/design/spec-agreement-review.md F-11
- type: schema
- content: An agreement verdict must not land in `--trust-report` or `.verified.json` beside the verification tiers; a downstream reader would read "agreed" as an assurance level, when it is a process attestation about how a contract was authored and carries no verification content. TRUST-PRE settled the same category error (a precondition must not floor a function's verified tier). Disposition: a separate artifact keyed by inventory row, in which the words `verified`, `asserted` and `trust` do not appear, emitted by the harness and not by `verify`.
