## Proposal authoring discipline (D2)

A design proposal that introduces a **boolean guard or predicate over computed values** (a warning that fires when a condition holds, a gate, an admissibility check) must include a **positive-witness row** in its edge-case enumeration: the minimal *concrete* input — an actual `def` + contract + candidate set, not an abstract description — that makes the guard fire. The `compiler-engineer` feasibility pass must **construct that witness**, not merely trace that the guard's inputs are computed and in scope.

Rationale: a firing predicate with no constructible witness is unsatisfiable by inspection. Input-availability ("are the values in scope at the emit site?") is not satisfiability ("can the guard be simultaneously true?"), and the gap between them is where a dead-code predicate hides — the design-workflow analogue of "write the failing test first." Precedent: [`expiring-intentional-proposal.md`](archive/dormant-explorations/expiring-intentional-proposal.md) (Rev 0.3, Meta-lesson) — a `W614` guard cleared three passes (language-team, compiler-engineer, a crux verification) on input-availability, then proved unsatisfiable at implementation because every *quiet* edge case was enumerated but the *firing* case was left abstract.

Enforcement is behavioral: `language-team` authors the witness row; `compiler-engineer` constructs it during the feasibility pass. This section binds proposal content, not a doc; it extends the working contract to the upstream authoring step so the same miss cannot recur.

### The archive invariant, and what enforces it

An archived doc's directory names whether its design **shipped**. That is the one claim an archive path makes here, and it is gated.

Each archived doc may declare, in its YAML frontmatter, a value from a closed four-term vocabulary:

| `archive-disposition:` | Meaning | Directory |
|---|---|---|
| `shipped` | the design is realized in the compiler | `shipped-design-specs/` |
| `superseded` | a successor shipped; this doc is kept for lineage | `shipped-design-specs/` |
| `dropped` | explored and abandoned; no part shipped | `dormant-explorations/` |
| `deferred` | not chosen and not abandoned; captured against a future need | `dormant-explorations/` |

[`scripts/doc_archive_gate.sh`](../scripts/doc_archive_gate.sh) (**DRIFT-DOC-3**) asserts that every declared value sits in the directory its side names, and fails CI otherwise. The field is opt-in: files without it are not gated, but the gate counts them and fails if that count grows, so a newly archived doc either declares the field or forces a visible bound raise.

The field governs **only** these two directories. Declaring it in `professor-reviews/`, `wasm-investigations/`, or any future archive category also fails the gate, rather than being read and ignored: a review's disposition is its proposal's, and a field the gate cannot check but silently accepts is how an opt-in convention stops covering anything.

**What the gate does and does not establish.** DRIFT-DOC-3 is a **consistency** gate, sibling of **DRIFT-CI-1** ([`scripts/version_gate.sh`](../scripts/version_gate.sh)): both compare records maintained inside this repository, and both detect *disagreement*. Neither can detect two records being wrong together. It is **not** a sibling of **DRIFT-CT-2** ([`scripts/doc_claims_gate.sh`](../scripts/doc_claims_gate.sh)), which executes the compiler and therefore has an oracle outside the repository. A status declaration is self-attestation, and the project already settled that such a channel admits no per-instance oracle (**F-002**, [`LLMLL.md`](../LLMLL.md) §4.4.6).

### When a new sub-categorization is proposed, decide it against these two criteria

Adjudicated 2026-07-26 via [`design/archive-organization-proposal.md`](design/archive-organization-proposal.md) Rev 2 and its [professor review](design/archive-organization-review.md). A directory tree carries exactly one facet, so the question is never "sub-categorize or not," it is *which* facet is worth the one tree available.

- **Criterion R (retrieval).** Does the partition materially narrow a scan a reader actually performs? Measure the **effective** class count, not the nominal one. The document-kind axis scored 2.5 effective classes against a nominal 9, with the modal class holding 61%, and the filename already carries the same information for 46 of 57 files. Declined. The feature-line axis scores worse: roughly 40 classes over 57 files. Declined.
- **Criterion I (inference guard).** Does misplacement make a reader conclude something false, independent of retrieval? The shipped-side/dormant split scores near zero on R and is kept anyway, because a reader who finds an abandoned design under `shipped-design-specs/` concludes it is in the compiler.

> **Why version buckets are retired (measured 2026-07-26).** The `v0.6/`…`v0.14/` bucketing was attempted and stopped, because the input does not exist. The shipped version is **not** recoverable from the archived docs themselves: their frontmatter carries `status:` and `date:` but no release, and the `Version:` lines in files like `int-2-boundary-shims.md` and `proof-artifact-proposal.md` mean *proposal revision*, not shipped release. Cross-referencing the canonical source does not close the gap either. Of 59 files, **32 are cited somewhere in `CHANGELOG.md` and 27 are cited nowhere in it**. Falling back to `INDEX.md`, this protocol, and the roadmap recovers a version-shaped string for only 16 of those 27, and those are *proximity* matches, not attributions: `cascading-refine-protocol-spike` yields v0.14.8, v0.14.12 **and** v0.14.13 with nothing to choose between them. **11 files yield no version signal at any source.**
>
> So version buckets fail both criteria: readers query `CHANGELOG.md` for version (R near zero), and for those 11 files a bucket would *induce* a false claim about when a feature shipped rather than prevent one (I negative). The general rule the archive now follows is **encode only what is immutable in a path**, which is also why Rust keeps `rust-lang/rfcs` `text/` flat and GHC keeps `proposals/` flat, both with status in document metadata rather than in the path.
>
> Cost was never the deciding argument, but it is not close either: roughly 158 links point into the directory, **38 of them in append-only `CHANGELOG.md` sections** (see the 2026-07-11 and 2026-07-18 sweep notes above, which left CHANGELOG links on stubs for exactly this reason). Any bucketing therefore requires breaking the append-only invariant or accepting permanently broken links in the release record.

> **Shipped-vs-not split (2026-07-26).** Three files were miscategorized and are now in [`archive/dormant-explorations/`](archive/dormant-explorations/): `expiring-intentional-proposal` (own status **"Abandoned (Rev 0.3)"**) and `spec-entropy-reason-string-proposal` (the F-002 terminal pair, Slice-2 dropped), both moved in the first sweep; and `contract-clause-refactor` (titled "Deferred Design", status "Deferred — captured for future reference", zero `CHANGELOG.md` and zero roadmap citations), which the first sweep missed because it searched for abandonment vocabulary and this document is deferred rather than abandoned. That miss is why the vocabulary is four-valued and why the invariant is now gated rather than swept by hand.

## Prose path citations (DRIFT-DOC-4)

A path written as a bare backtick span in running text, `docs/design/foo.md`, is followed by no tool and rots silently when the file moves. [`scripts/doc_path_lint.py`](../scripts/doc_path_lint.py) reports the ones that no longer resolve.

**It is advisory and exits 0 by design.** The other three gates assert something with a definite truth value; this one cannot, because a rationale legitimately names a location that does not exist and whose non-existence is the point of the sentence. Making it fail-closed would demand that correct prose be mangled to appease it, and it would be the first gate here that can be wrong about correct input. Its value is the report in the CI log and the `test_clean_on_live_repo` regression test, not a merge block.

Four classes are excluded, and they are what make the signal usable: **historical files** (postmortems, frozen run records, append-only `CHANGELOG.md`, archived docs, all of which describe the tree as it was), **historical lines** (a living doc holding a past-tense sentence, as in the pre-planned-archive-moves table above), **placeholders** (`postmortem-NNN.md`, elided paths), and **link labels** whose target already resolves. `ALLOW` in the script records the individually-verified exceptions, one reason per entry.

When a doc-lead sweep archives or renames a file, the prose that names it moves in the same change. The lint tells you which prose that is.

**Roadmap-internal cross-references cite a row's tag name or a heading anchor, never a line number.** [`compiler-team-roadmap.md`](compiler-team-roadmap.md) is a table, so inserting one row shifts every line below it: a cite like `` (`:242`) `` is invalidated by an edit that has nothing to do with it, and the lint above cannot see the breakage because there is no path to resolve. Measured 2026-08-02: two such cites had already drifted (IFACE-CONFORM cited at `:53` while sitting at `:61`, the lifted-exclusions note cited at `:242` while sitting at `:250`), and both drifted a second time in the same session as new rows landed. Write **IFACE-CONFORM**, or [`#whats-not-on-this-roadmap-and-why`](compiler-team-roadmap.md#whats-not-on-this-roadmap-and-why). This binds design docs citing into the roadmap as much as the roadmap citing itself. Line cites into *source* files (`TypeCheck.hs:1860-1865`) are unaffected: a code move shows up in the diff, and the precision is worth the cost there.

**A version mention in prose carries an arrival verb, or it reads as a currency claim.** A bare `` `trust_report_version` 1.5.0 `` at the end of a paragraph says *current* to every reader and rots at the next bump, even where the author meant *this is where the field arrived*; the repair is the verb, not the number (`effect_summary` arrived at obligation-report `schema_version` `0.12.0`, [`LLMLL.md`](../LLMLL.md) §11.2). A **currency** claim about a schema belongs only to the P1 canonical source that already owns that schema (the `const` in [`llmll-trust-report.schema.json`](llmll-trust-report.schema.json), the `version` field in [`llmll-ast.schema.json`](llmll-ast.schema.json)), so one bump edits one place. Measured 2026-08-05: renumbering a mention in place is the failure mode, not the fix. On the v0.14.2 release pass (`60bbc9c`) the CDP paragraph's true arrival version `1.2.0` was overwritten with `1.4.0`, which destroyed the LT-CDP attribution and asserted a bump the emitter never made.
